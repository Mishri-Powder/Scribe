This is a highly practical constraint. Relying on AI or human grading introduces latency, privacy concerns, and complexity. 

To keep this **100% client-side, zero-AI, and low-processing**, the system must rely on **deterministic, predefined rules** set by the book's author. The JavaScript only needs to check for exact matches, array order, or DOM attributes.

Here are the best active learning tools that require the user to *do* something, can be **instantly and automatically checked by simple JavaScript**, and are highly neurodivergent-friendly.

---

### 1. Kinesthetic & Visual Manipulation (Drag, Drop, Sort)
These require zero typing (reducing dysgraphia/ADHD friction) and are checked via simple DOM attribute matching.

*   **Category Sorting Bins:** 
    *   **The Task:** The user drags 5-10 concept cards into 2 or 3 labeled bins (e.g., "Cause" vs. "Effect", or "Fact" vs. "Opinion").
    *   **How it’s Checked:** Each card has a `data-correct-bin="cause"` attribute. When dropped, JS checks if the parent container's ID matches the card's data attribute. `if (card.dataset.correctBin === dropZone.id) { markCorrect(); }`
    *   **ND Benefit:** Tactile, visual, and feels like a puzzle rather than a test. Immediate, non-punitive feedback (e.g., the card gently snaps back to the start if wrong, or glows green if right).
*   **Sequential Ordering:** 
    *   **The Task:** The user is given 4-6 scrambled steps of a process (e.g., steps of the scientific method, chronological historical events) and must drag them into the correct top-to-bottom order.
    *   **How it’s Checked:** JS reads the current order of the DOM elements (or an array of their IDs) and compares it to the author's predefined correct array. `if (JSON.stringify(currentOrder) === JSON.stringify(correctOrder)) { success(); }`
    *   **ND Benefit:** Directly trains executive functioning (sequencing) without requiring the user to generate the steps from memory.

### 2. Frictionless Recall (No Typing Required)
Free-text input is a nightmare for auto-checking (capitalization, extra spaces, typos cause false negatives, which triggers Rejection Sensitive Dysphoria). Use these instead:

*   **Dropdown Cloze Deletion (Fill-in-the-Blank):**
    *   **The Task:** A paragraph has missing words. Instead of typing, the user clicks a dropdown menu embedded in the sentence to select the correct word from 3-4 options.
    *   **How it’s Checked:** The `<select>` element has a `value`. JS simply checks `if (selectElement.value === "correct_answer")`. Zero string parsing needed.
    *   **ND Benefit:** Eliminates spelling anxiety and working memory overload. The user only has to *recognize* the right answer, not *recall and spell* it.
*   **Interactive "Spot the Error" (Proofreading):**
    *   **The Task:** The author intentionally writes a paragraph with 1 or 2 factual errors or swapped terms. The user must click on the incorrect word(s).
    *   **How it’s Checked:** The incorrect words are wrapped in `<span data-is-error="true">`. A click event listener checks `if (event.target.dataset.isError === "true")`.
    *   **ND Benefit:** Taps into the "hyperfocus" and pattern-recognition strengths common in autism. It feels like a "find the hidden object" game.

### 3. Logic & Connection Building
*   **Matching Pairs (Linking):**
    *   **The Task:** Two columns. Left column has terms, right column has definitions. The user clicks a term, then clicks its matching definition.
    *   **How it’s Checked:** Each term and definition shares a hidden `data-pair-id="4"`. JS checks if the two clicked elements have the same `data-pair-id`.
    *   **ND Benefit:** Visual, spatial, and provides clear, binary feedback. Can be styled as a calming, low-stakes matching game.
*   **Simple Variable Sliders (Cause & Effect):**
    *   **The Task:** "If the population of wolves increases, what happens to the deer population?" The user drags a slider labeled "Deer Population" to "Decreases".
    *   **How it’s Checked:** The slider has discrete values (e.g., `value="decrease"`). JS checks the value on change.
    *   **ND Benefit:** Makes abstract concepts concrete and manipulable. 

### 4. Metacognitive Scaffolding (The "Rubric" Checklist)
Instead of the computer grading an open-ended thought, the computer provides the *checklist*, and the **user grades themselves**. This builds massive self-awareness.

*   **Guided Self-Assessment Checklists:**
    *   **The Task:** After a chapter, there is a text area: *"Write a 2-sentence summary of this chapter."* Below it is a checklist: 
        - [ ] I mentioned the main character's name.
        - [ ] I mentioned the central conflict.
        - [ ] I wrote at least two sentences.
    *   **How it’s Checked:** The JS *only* checks if the checkboxes are ticked and if the text area length is > 0. It does **not** read the text. It rewards the user for completing the *process*.
    *   **ND Benefit:** Removes the anxiety of "Is this good enough?" The system doesn't judge the content; it just validates that the user followed the structured steps. This is incredibly empowering and reduces task paralysis.

---

### The Golden Rules for Auto-Checked ND Tools

1. **Never use strict free-text matching.** If you must use a text input, use a highly forgiving JS function that lowercases, trims whitespace, and checks against an *array* of acceptable answers: 
   ```javascript
   const acceptableAnswers = ["mitosis", "cell division", "mitosis "];
   const isCorrect = acceptableAnswers.includes(userInput.toLowerCase().trim());
   ```
2. **Feedback must be immediate and gentle.** Do not use jarring buzzers or red "X"s. If a drag-and-drop is wrong, the piece should just gently slide back to its original position, perhaps with a subtle tooltip: *"Hint: Check the definition in paragraph 2."*
3. **Allow infinite retries without penalty.** There should be no "3 strikes and you're locked out." The goal is mastery, not punishment.

### Copy-Paste Example: The Auto-Checking Dropdown Cloze

Here is a complete, single-file, zero-dependency example of the most robust, ND-friendly, auto-checkable active learning tool: **The Dropdown Cloze**.

```html
<!DOCTYPE html>
<html lang="en">
<head>
<meta charset="UTF-8">
<title>Active Learning Example</title>
<style>
  :root {
    --bg: #fdfbf7; /* Soft, low-glare sepia */
    --text: #2c3e50;
    --correct: #27ae60;
    --incorrect: #e74c3c;
    --accent: #3498db;
  }
  body {
    font-family: 'Segoe UI', Tahoma, Geneva, Verdana, sans-serif;
    background-color: var(--bg);
    color: var(--text);
    line-height: 1.8; /* High line height for readability */
    max-width: 700px;
    margin: 40px auto;
    padding: 20px;
  }
  .cloze-sentence {
    font-size: 1.2rem;
    margin-bottom: 20px;
    padding: 15px;
    border-left: 4px solid var(--accent);
    background: rgba(52, 152, 219, 0.05);
    border-radius: 4px;
  }
  select {
    font-size: 1rem;
    padding: 4px 8px;
    border: 2px solid var(--accent);
    border-radius: 4px;
    background: white;
    cursor: pointer;
    margin: 0 4px;
  }
  select.correct {
    border-color: var(--correct);
    background-color: rgba(39, 174, 96, 0.1);
    color: var(--correct);
    font-weight: bold;
  }
  select.incorrect {
    border-color: var(--incorrect);
    background-color: rgba(231, 76, 60, 0.1);
    animation: gentleShake 0.4s ease-in-out;
  }
  .feedback {
    font-size: 0.9rem;
    margin-top: 10px;
    min-height: 1.5em;
    font-weight: 500;
  }
  .feedback.success { color: var(--correct); }
  .feedback.hint { color: #d35400; }

  @keyframes gentleShake {
    0%, 100% { transform: translateX(0); }
    25% { transform: translateX(-4px); }
    75% { transform: translateX(4px); }
  }
</style>
</head>
<body>

  <h2>Chapter 1: The Cell</h2>
  <p>Read the sentence below and select the correct words to complete the thought.</p>

  <div class="cloze-sentence" id="activity-1">
    The 
    <select data-answer="mitochondria" data-hint="Think: 'powerhouse of the cell'">
      <option value="">-- choose --</option>
      <option value="nucleus">nucleus</option>
      <option value="mitochondria">mitochondria</option>
      <option value="ribosome">ribosome</option>
    </select>
    is often called the powerhouse of the cell because it generates most of the cell's supply of 
    <select data-answer="atp" data-hint="This is the energy currency of the cell.">
      <option value="">-- choose --</option>
      <option value="water">water</option>
      <option value="atp">ATP</option>
      <option value="protein">protein</option>
    </select>.
  </div>

  <div class="feedback" id="feedback-1"></div>

  <script>
    // Simple, zero-dependency auto-checker
    document.querySelectorAll('select').forEach(select => {
      select.addEventListener('change', function() {
        const userAnswer = this.value;
        const correctAnswer = this.dataset.answer;
        const hint = this.dataset.hint;
        const feedbackEl = document.getElementById('feedback-1');
        
        // Reset classes
        this.classList.remove('correct', 'incorrect');
        
        if (userAnswer === "") {
          feedbackEl.textContent = "";
          return;
        }

        if (userAnswer.toLowerCase() === correctAnswer.toLowerCase()) {
          this.classList.add('correct');
          feedbackEl.textContent = "✓ Correct! Well done.";
          feedbackEl.className = "feedback success";
          checkOverallCompletion();
        } else {
          this.classList.add('incorrect');
          feedbackEl.textContent = `Not quite. Hint: ${hint}`;
          feedbackEl.className = "feedback hint";
        }
      });
    });

    function checkOverallCompletion() {
      // Check if ALL selects in the activity are correct
      const selects = document.querySelectorAll('#activity-1 select');
      const allCorrect = Array.from(selects).every(s => s.value.toLowerCase() === s.dataset.answer.toLowerCase());
      
      if (allCorrect) {
        document.getElementById('feedback-1').textContent = "✓ Excellent! You've mastered this concept. Ready for the next section.";
        // Optional: Save progress to localStorage
        localStorage.setItem('chapter1_activity1', 'complete');
      }
    }

    // Restore state on load (ND-friendly: never lose progress)
    window.addEventListener('DOMContentLoaded', () => {
      if (localStorage.getItem('chapter1_activity1') === 'complete') {
        document.querySelectorAll('#activity-1 select').forEach(s => {
          s.value = s.dataset.answer;
          s.classList.add('correct');
        });
        document.getElementById('feedback-1').textContent = "✓ Previously completed. Great job!";
        document.getElementById('feedback-1').className = "feedback success";
      }
    });
  </script>

</body>
</html>
```

### Why this specific pattern works perfectly for your constraints:
1. **Zero AI/Backend:** It’s just a simple string comparison (`===`).
2. **Low Processing:** The browser does this in microseconds.
3. **ND-Friendly:** 
   - No typing (eliminates spelling frustration).
   - Immediate, gentle feedback (green highlight or a hint, no harsh penalties).
   - Progress is saved to `localStorage`, so if the user gets distracted and closes the tab, their success is waiting for them when they return (reducing task-initiation friction).
