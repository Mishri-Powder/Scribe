This is a fantastic constraint. In fact, for neurodivergent (ND) learners, **removing subjective, human/AI-graded questions is often a massive benefit**. 

Subjective grading creates ambiguity ("Is my answer good enough?"), which can trigger anxiety and Rejection Sensitive Dysphoria (RSD) in ND individuals. Objective, internally checked questions provide **absolute clarity, immediate feedback, and predictable outcomes**, which are incredibly soothing and satisfying for the autistic/ADHD brain.

Here are active learning tools that promote deep understanding, require **zero AI or human grading**, and can be checked instantly by a few lines of JavaScript.

---

### 1. Sequencing and Ordering (Logic & Flow)
*Learning mechanism: Understanding chronological order, cause-and-effect, or step-by-step processes.*

*   **Drag-and-Drop Timelines / Process Maps:** Scramble the steps of a process (e.g., the steps of a chemical reaction, or events in a historical timeline). The user drags them into the correct 1-to-5 order.
    *   **How to check (JS):** When the user clicks "Check", get an array of the IDs of the dragged items and compare it to the correct array. `if (userArray.toString() === correctArray.toString()) { success(); }`.
    *   **ND Benefit:** Highly tactile, provides a clear "start" and "finish" state, and satisfies the need for systemizing and organizing.
*   **"Code/Logic Scramble":** If the book teaches coding or math, provide the lines of a proof or script in a jumbled list. The user must arrange them logically. 
    *   **How to check (JS):** Same array matching as above. You can also check for nested items (e.g., an indented `if` statement must be placed inside the parent `for` loop container).

### 2. Categorization and Sorting (Pattern Recognition)
*Learning mechanism: Distinguishing between concepts, identifying traits, and building mental models.*

*   **Concept Buckets (Sorting):** Provide a list of terms, facts, or quotes at the top of the screen, and 2 to 4 "buckets" below (e.g., "Mitosis" vs. "Meiosis", or "Fact" vs. "Opinion"). The user drags the items into the correct buckets.
    *   **How to check (JS):** Store the correct mapping in a simple JSON object: `const correctAnswers = { "term1": "bucketA", "term2": "bucketB" };`. Loop through the buckets and check if the items inside match the JSON object.
    *   **ND Benefit:** Appeals heavily to the autistic trait of categorization. It turns reading into a highly satisfying sorting game.
*   **Interactive Venn Diagrams:** Provide three drop zones: "Concept A Only", "Concept B Only", and "Both". 
    *   **How to check (JS):** Same JSON mapping logic as the buckets. 

### 3. Precision Highlighting (Focus & Attention)
*Learning mechanism: Scanning for specific information, identifying grammatical structures, or spotting logical fallacies.*

*   **"Spot the Error" (Click to Identify):** Present a paragraph or equation that contains exactly *one* deliberate mistake. The user must click on the exact word or number that is wrong.
    *   **How to check (JS):** Wrap every word/number in a `<span>` with a unique ID or data attribute. `document.querySelectorAll('span').forEach(span => { if(span.dataset.isError === 'true') { markCorrect(); }})`.
    *   **ND Benefit:** Turns reading into a "Where's Waldo" game. This is excellent for ADHD brains that need high-stimulation, gamified focus to read dense text.
*   **Targeted Highlighting:** Instead of "Highlight the main idea" (which is subjective), ask: *"Click the 3 verbs that describe the protagonist's physical actions in this paragraph."* 
    *   **How to check (JS):** Pre-tag the correct words with a hidden CSS class (e.g., `class="target-verb"`). Count how many `target-verb` elements the user has clicked/activated. If count === 3, they win.

### 4. Exact Recall & Fill-in-the-Blank (Memory)
*Learning mechanism: Active recall of specific terminology, formulas, or core definitions.*

*   **Contextual "Mad Libs" (Cloze Deletion):** Present a summary paragraph with 5 key words blanked out. The user types the missing words.
    *   **How to check (JS):** To avoid frustrating exact-match failures (e.g., typing "colour" instead of "color"), provide an array of accepted synonyms for each blank. 
    ```javascript
    const acceptedAnswers = ["car", "auto", "vehicle"];
    const userAnswer = input.value.trim().toLowerCase();
    if (acceptedAnswers.includes(userAnswer)) { markCorrect(); }
    ```
    *   **ND Benefit:** Low ambiguity. The user knows exactly what level of detail is required.
*   **Flashcard Multiple Choice / Matching:** The user creates flashcards, but the system forces them to be Multiple Choice or Term-to-Definition matching pairs.
    *   **How to check (JS):** Standard multiple-choice logic (checking if the selected radio button value matches the correct key). 

### 5. Metacognition & Self-Tracking (Zero "Wrong" Answers)
*Learning mechanism: Thinking about one's own thinking, predicting outcomes, and tracking personal confidence.*

*   **Prediction Logs:** Before reading a chapter, show the chapter title and ask: *"What do you think this chapter is about? Type 1 sentence."* After they read it, show a simple toggle: *"Was your prediction correct? Yes / Sort of / No."*
    *   **How to check (JS):** You don't check the text! You just save their text to `localStorage` and record which toggle button they clicked.
    *   **ND Benefit:** Builds anticipation (dopamine) before reading. The "checking" is just self-reflection, removing all performance anxiety.
*   **Confidence Sliders (Pre/Post Testing):** Before a section, show a slider: "Rate your confidence in this topic from 1 to 10." After the section, show it again. 
    *   **How to check (JS):** Just records the numerical value. 
    *   **ND Benefit:** Visualizes their own progress. Many ND learners suffer from imposter syndrome; seeing their confidence slider jump from a 2 to an 8 provides concrete, visual proof that they are learning.

---

### Crucial Design Rules for ND "Internally Checked" Tools

If you are strictly using JS to check answers, you must handle **wrong answers** carefully to avoid triggering Rejection Sensitive Dysphoria (RSD) or demand avoidance.

1.  **Never use the word "Incorrect" or "Wrong":** 
    *   *Bad:* ❌ "Wrong! The answer is 42." (Triggers shame).
    *   *Good:* 🔄 "Let's recalibrate. 42 is the target. Let's try again." (Frames it as a mechanical adjustment, not a personal failure).
2.  **Highlight the *Difference*, not just the error:** 
    *   If a user drags 5 steps into a sequence and gets 3 right, 2 wrong: Highlight the 3 correct ones in green (Dopamine!), and gently bounce the 2 wrong ones back to the starting area with a soft "reset" sound. Don't wipe their whole progress.
3.  **Offer a "Show Me" (Hint) Button:**
    *   Executive dysfunction can cause a user to get completely "stuck" on a drag-and-drop puzzle. If they stare at it for 30 seconds without moving, fade in a button that says *"Show me the first step"*. It places one piece in the correct spot to unblock their momentum.
4.  **Instant Audio/Visual Feedback:**
    *   When they get a piece right, play a satisfying, subtle "click" or "chime" sound (use the Web Audio API or `<audio>` tags). Make the piece snap into place with a satisfying CSS animation. ND brains thrive on immediate, sensory feedback loops.

### Summary of the JS Architecture for this:

To do this with zero processing lag, structure your HTML and JS like this:

```html
<!-- 1. Embed the "Answer Key" invisibly in the HTML -->
<script type="application/json" id="chapter-3-quiz">
  {
    "sequence": ["step_a", "step_b", "step_c"],
    "buckets": { "term1": "bucket1", "term2": "bucket2" },
    "blanks": { "blank1": ["mitochondria", "mito", "powerhouse"] }
  }
</script>

<!-- 2. The Interactive UI -->
<div class="sorter">
   <div class="term" draggable="true" id="term1">Term 1</div>
   <div class="bucket" id="bucket1">Bucket 1</div>
</div>

<!-- 3. The JS Checking Logic (Extremely lightweight) -->
<script>
  // Parse the embedded JSON once on load
  const answerKey = JSON.parse(document.getElementById('chapter-3-quiz').innerText);

  function checkBuckets() {
      let allCorrect = true;
      // Iterate through the answer key
      for (let term in answerKey.buckets) {
          const correctBucketId = answerKey.buckets[term];
          const termElement = document.getElementById(term);
          const currentParentId = termElement.parentElement.id;
          
          if (currentParentId !== correctBucketId) {
              allCorrect = false;
              termElement.classList.add('recalibrate-bounce'); // Visual feedback
          } else {
              termElement.classList.add('locked-green'); // Visual dopamine
          }
      }
      if (allCorrect) playSuccessSound();
  }
</script>
```

By sticking to these internally checkable, objective formats, your single HTML file becomes an incredibly fast, offline-capable, and psychologically safe learning environment for neurodivergent minds.
