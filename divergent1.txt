Designing a learning tool for neurodivergent (ND) brains—specifically ADHD and Autism—requires shifting the focus from **standardized presentation** to **extreme user customization and cognitive offloading**. 

What helps one ND person might overwhelm another, so the golden rule is: **Give the user control over their environment.**

Here are the best practices and features to make your client-side HTML/JS book highly neurodivergent-friendly, categorized by the specific challenges they address.

---

### 1. Sensory & Visual Regulation (Crucial for Autism & ADHD)
ND individuals often experience sensory processing differences. The UI must not cause sensory overload.

*   **Granular Theme Control:** Don’t just offer "Light/Dark." Offer low-saturation/pastel themes, high-contrast themes, and specific color overlays (like sepia or soft blue) that reduce eye strain. Let users change the background and text colors independently.
*   **Typography & Spacing Controls:** Provide controls for font family (include a dyslexia-friendly font like *OpenDyslexic* or *Atkinson Hyperlegible*), font size, line height, and letter spacing. Increased spacing drastically improves reading comprehension for many ND readers.
*   **"Reduce Motion" Toggle:** Animations, parallax scrolling, and auto-playing elements can be deeply distracting or physically nauseating. Include a master toggle that instantly disables all CSS transitions and JS animations.
*   **Focus/Spotlight Mode:** For ADHD, peripheral vision can be highly distracting. Create a "Focus Mode" that dims the entire page except for the specific paragraph or line the user is currently reading (using CSS `backdrop-filter` or an overlay with a "cutout").

### 2. Cognitive Load & Executive Function (Crucial for ADHD)
ADHD often involves working memory deficits and executive dysfunction (difficulty starting tasks, organizing, and sustaining effort).

*   **The "Brain Dump" Scratchpad:** ADHD brains generate random, distracting thoughts while reading. If they stop to write it in another app, they lose their place. Build a persistent, collapsible side-panel (saved to `localStorage`) where they can rapidly type out random thoughts, questions, or links without leaving the reading flow.
*   **Bionic Reading / Guiding:** Use JS to dynamically bold the first few letters of every word (e.g., **Ada**PT **th**IS **fo**R **AD**HD). This creates artificial fixation points that guide the eye across the page, significantly speeding up reading and reducing mental fatigue.
*   **Micro-Chunking & "TL;DR" Toggles:** Break text into small, digestible paragraphs. At the top of every long section, include a `<details>` toggle for a "TL;DR" (Too Long; Didn't Read) summary. On days when executive function is low, the user can just read the summaries.
*   **Visual Dopamine & Progress Tracking:** ADHD brains crave dopamine. Use visual progress bars, chapter completion checkmarks, or subtle confetti/animations (if motion is enabled) when a chapter is finished. Make the progress *visible* and *satisfying*.
*   **"Start Small" Prompts:** If a chapter is long, add a button that says "Read just the first 3 paragraphs." This lowers the barrier to entry and helps overcome task paralysis.

### 3. Navigation & Predictability (Crucial for Autism)
Autistic learners often thrive on predictability, clear structure, and literal interpretation. Ambiguity causes anxiety.

*   **Persistent, Literal Wayfinding:** Never let the user get lost. Keep a sticky Table of Contents. Use literal, unambiguous labels (e.g., use "Go to Chapter 3: The Heart" instead of "Dive Deeper"). Always show exactly where they are in the document (e.g., "Page 4 of 20" or a visual progress bar).
*   **Consistent UI & No "Gotchas":** Icons should always mean the same thing. Buttons should look like buttons. Avoid hidden menus, hover-only interactions, or elements that change behavior unexpectedly. 
*   **Clear State Indicators:** If a button is loading, show a spinner. If a section is expanded, change the chevron icon. If a quiz question is answered, clearly show green/red. Never leave the user guessing what the system is doing.
*   **Glossary & Context Pop-ups:** Autistic individuals might take metaphors or idioms literally, or get stuck on an unknown word. Use JS to detect complex vocabulary and allow users to click it for a literal, clear definition in a non-intrusive tooltip, without navigating away from the text.

### 4. Memory, Retention & Multi-Sensory Learning
ND brains often benefit from dual-coding (processing information through multiple senses) and active engagement.

*   **Text-to-Speech (TTS) with Synced Highlighting:** Use the Web Speech API to read the text aloud while simultaneously highlighting the current word. This combines visual and auditory processing, which heavily aids retention for many ND learners. Allow them to adjust the reading speed.
*   **Interactive "Flip" Cards for Key Concepts:** Instead of just stating a definition, hide it. Make the user click or tap to reveal it. The physical action of revealing the answer keeps the ADHD brain engaged and tests active recall.
*   **Visual Concept Mapping:** Use an embedded JS canvas library to let users visually link concepts. Autistic "special interests" often involve deep, systemic thinking; allowing them to visually map how Chapter 2 connects to Chapter 5 caters to this systemic processing style.
*   **Audio/Visual Cues for Transitions:** When moving from one chapter to the next, use a distinct, gentle sound cue or a clear visual divider. This helps signal to the brain that the context is changing, preventing "context bleed."

### 5. Emotional Regulation & Frictionless Experience
Learning should not induce shame or frustration.

*   **Forgiving Spaced Repetition:** If you include flashcards or review quizzes, do *not* use punitive streaks (like Duolingo's loss of a streak). If an ADHD user misses 4 days, they will feel shame and abandon the tool. Use a "forgiving" algorithm that just resumes where they left off without penalty.
*   **No Auto-Playing Media:** Never auto-play audio or video. It violates sensory boundaries and startles the user. Always require a deliberate click.
*   **Customizable Hotkeys:** Allow users to map keyboard shortcuts for navigation (e.g., `J` for next paragraph, `K` for previous, `Space` to toggle TTS). This caters to users who prefer keyboard navigation or have motor skill differences (Dyspraxia).

### How to Implement This in a Single HTML File

To keep this manageable without a backend, rely heavily on **CSS Variables** and **`localStorage`/`IndexedDB`**.

**1. The Settings Panel (The Control Center)**
Create a settings modal that writes directly to CSS variables and `localStorage`.
```javascript
// Example: Saving user preferences
function savePreferences(prefs) {
    localStorage.setItem('nd-book-prefs', JSON.stringify(prefs));
    // Apply to CSS variables
    document.documentElement.style.setProperty('--font-size', prefs.fontSize + 'px');
    document.documentElement.style.setProperty('--line-height', prefs.lineHeight);
    document.documentElement.style.setProperty('--bg-color', prefs.bgColor);
}
```

**2. The "Brain Dump" Scratchpad**
Use a simple `contenteditable` div or `<textarea>` that auto-saves on every keystroke.
```javascript
const scratchpad = document.getElementById('scratchpad');
scratchpad.addEventListener('input', (e) => {
    localStorage.setItem('brain-dump', e.target.innerText);
});
// Load on startup
scratchpad.innerText = localStorage.getItem('brain-dump') || '';
```

**3. Bionic Reading Implementation**
Use a lightweight JS function to wrap the first few letters of words in a `<b>` tag when the user toggles the feature. (Note: Do this on a cloned DOM or use CSS `::first-letter` tricks if possible to avoid messing up the actual text selection, or use a library like `bionic-reading` via CDN).

**4. Focus Mode (Spotlight)**
Use CSS and JS to track the mouse or the currently active paragraph.
```css
/* CSS for focus mode */
body.focus-mode p {
    opacity: 0.2;
    transition: opacity 0.3s;
}
body.focus-mode p:hover, 
body.focus-mode p.active-paragraph {
    opacity: 1;
}
```

### Summary Checklist for ND Friendliness:
- [ ] Can the user change the colors, fonts, and spacing?
- [ ] Can the user turn off all animations?
- [ ] Is there a place to write down distracting thoughts without leaving the page?
- [ ] Is the navigation literal, consistent, and always visible?
- [ ] Can the user listen to the text while reading it?
- [ ] Are long texts broken into small chunks with summaries?
- [ ] Does the system forgive missed days/mistakes without inducing shame?

By building these features, you transition the book from a static document into an **adaptive learning environment** that meets the user exactly where their brain is on any given day.
